# Paper v2 Evidence Manifest

The active paper-v2 figures and notebooks consume only the semantic `v2_*`
artifacts listed below. They are generated by:

```bash
uv run python scripts/paper/v2_evidence.py
```

The script validates canonical P2/P3 rows, reconstructs the backed/generated
spill identity from machine artifacts where available, distinguishes controlled
$H=0$ diagnostics from the production portfolio, and writes a provenance
ledger to `v2_evidence_manifest.csv`.

## Active derived tables

- `results/autoresearch_v2/round12_audited_p1.json` — freshly regenerated P1
  logical-lifetime metrics for all six public cases.  Every row is evaluator
  valid with zero violations.  L1/UB are logical ALLOC--FREE byte peaks and
  L0A/B/C are logical active-buffer counts; they are not physical P2 residency
  traces.  The supplementary table reports the substantial negative L0-count
  results as well as the favorable components.
- `v2_public_p2_p3.csv` — Scalable-v2 P2 extra traffic and P3 latency versus
  the matching official artifacts for all six public cases.
- `v2_conv0_method_path.csv` — legacy, Scalable v2, cost-aware repair,
  fixed-order exact, and official P2 values for Conv 0.
- `v2_conv0_cost_identity.csv` — backed volume $C$, generated volume $D$,
  $V=C+D$, generated surcharge $D$, and $E=V+D$.
- `v2_component_attribution.csv` — selected, non-factorial $H=0$ traffic
  configurations for all six cases, plus the separately sourced actual
  predecessor. The $H=0$ reference is not the production predecessor.
- `v2_all_cases_cost_decomposition.csv` — official-versus-production-Scalable-v2
  paired $E=V+D$ accounting for all six cases, with production components read
  directly from `round11_audited_p2.json`.
- `v2_p2_p3_decoupling.csv` — within-portfolio P3-minus-P2 traffic and latency
  changes; it does not mix different official artifacts.
- `v2_exact_evidence_scope.csv` — discrete fixed-order traffic evidence. FA 0
  / `id_raw` and Conv 0 / `unlock_frontier` and `/p1` are machine-checkable
  traffic-optimal certificates. Matmul 0 and FA 1 are machine-checkable
  feasible artifacts with nonzero traffic gaps. Conv 1 and Matmul 1 remain
  provisional run-log metadata. This is not a scaling experiment or a
  benchmark-tie-break optimality claim.
- `v2_exact_scope_summary.json` — row-level exact provenance and scope.
- `v2_capacity_boundary.csv` — controlled $H=0$ Conv 0 L1-capacity sweep,
  including pinned-set infeasibility. At 3,072 bytes it selects `capfit_id`.
- `v2_synthetic_boundary.csv` — internal, non-canonical-validated
  non-regression diagnostics versus a cost-blind ordering comparator and
  iter038.
- `v2_synth_suite.csv` / `v2_synth_summary.csv` — production portfolio run on
  the 36-instance internal synthetic suite with canonical-evaluator validation
  (zero violations on every row), per-instance $E$/$C$/$D$ against the previous
  portfolio and the four literature-style order baselines plus best-of-8
  random orders; generated by `scripts/paper/v2_synth_suite.py`.
- `v2_synth_oracle.csv` — production solver versus the fixed-order CP-SAT
  traffic optimum computed on the solver's own selected order for the
  8-instance oracle set; all eight runs match the optimum exactly.
- `v2_synth_pair.csv` — production and previous-portfolio results on the
  clean/dirty reserve pair, canonically validated.
- `v2_evidence_manifest.csv` — source-to-claim mapping for the files above.

## Active figures

Generated as 300-dpi PNG for executed notebooks and PDF/PNG for the paper:

- `public_p2_p3_vs_official` — signed relative deltas, with P2 and P3 in
  separate panels.
- `conv0_method_decomposition` — controlled P2 method path.
- `spill_cost_identity` — direct $E=C+2D=V+D$ accounting.
- `exact_certificate_scope` — Conv 0 certificate plus discrete research-oracle
  scope; the oracle is not integrated into the default solver.
- `robustness_boundaries` — capacity and synthetic boundaries.
- `component_attribution` — selected controlled traffic ablations and their
  deviation from a naive additive extrapolation; not a factorial interaction
  estimate.
- `all_cases_cost_decomposition` — paired $\Delta E=\Delta V+\Delta D$
  accounting against official P2 artifacts.
- `p2_p3_decoupling` — within-portfolio P2-to-P3 traffic--latency tradeoff.
- `e1_dag_example` — backed/generated objective schematic used by the model.

## Active notebooks

- `notebooks/02_paper_figures/` builds the eight evidence figures and exact
  numeric tables from fragments.
- `notebooks/03_results_report/` is the audited narrative report.

Both notebooks must be rebuilt with `--execute`; `.ipynb` files are generated
artifacts and are never edited manually.

## Legacy archive boundary

Older `e*`, `x*`, `prob_*`, and inventory outputs remain on disk for
reproducibility and data-problem notebooks, but they are not consumed by the
active paper-v2 figure or results-report manifests. In particular, the legacy
headline and E5 peak-residency evidence are retired and must not support paper
claims.
