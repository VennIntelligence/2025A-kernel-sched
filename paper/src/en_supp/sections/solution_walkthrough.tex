\section{Solver Implementation and Complete Walkthrough}\label{sec:supp-solution}

This section first separates three solver roles and then expands how a DAG becomes a validated artifact. The roles are the default scalable portfolio, offline cost repair used only for mechanism studies, and a fixed-topological-order CP-SAT oracle. The latter two are not hidden stages of production \texttt{solve}.

\subsection{Canonical scalable solver}

For P2/P3, production generates four structural topological orders: \texttt{unlock-frontier}, \texttt{capfit-id}, the P1 memory order, and \texttt{id-raw}. Only the first is new in v2. The other three provide historical and structural diversity and are not relabeled as cost-aware order generators. None of the four reads backed/generated labels. Class information enters only the two victim scores and the true traffic computation and final selection over complete candidates. The phrase ``purely structural'' applies only to the new \texttt{unlock-frontier}: the retained P1 fallback contains \texttt{D2S}-, \texttt{COPY-IN}-, and \texttt{MOVE}-specific tie-breaks for certain input shapes. We therefore do not call the canonical solver as a whole motif-agnostic; the narrow valid statement is that frontier reads neither instance names, operation motifs, nor buffer classes.

\texttt{unlock-frontier} schedules ready FREE nodes first, then the minimum-ID ready operation. When only ALLOC nodes remain, it finds the minimum-ID consumer whose remaining predecessors are all ready and completes that predecessor group. This avoids a stream of single-input transfers indefinitely starving a multi-input operation.

\begin{algorithm}[H]
\caption{Dependency-frontier topological order}\label{alg:supp-frontier}
\begin{algorithmic}[1]
\Require DAG instance $I$
\State Partition zero-indegree nodes into $Q_f,Q_o,Q_a$; $S\gets[\ ]$
\While{$Q_f\cup Q_o\cup Q_a\ne\emptyset$}
  \If{$Q_f\ne\emptyset$} \State $v\gets$ maximum-ID node in $Q_f$
  \ElsIf{$Q_o\ne\emptyset$} \State $v\gets$ minimum-ID node in $Q_o$
  \Else
    \State $u\gets$ minimum-ID consumer whose unfinished predecessors are all in $Q_a$
    \State $v\gets$ minimum-ID ready predecessor of $u$
    \If{no such $u$ exists} \State $v\gets$ minimum-ID node in $Q_a$ \EndIf
  \EndIf
  \State append $v$ to $S$; update indegrees and $Q_f,Q_o,Q_a$
\EndWhile
\State \Return $S$
\end{algorithmic}
\end{algorithm}

Each topological order runs true best-fit address placement: among all sufficiently large free intervals, choose the shortest and then the lowest-address tie; merge adjacent intervals on release. If no contiguous hole fits, the placer chooses a victim not pinned by the next operation, inserts spill-out, and releases its entire address segment until placement succeeds. A later access or FREE inserts spill-in, which may place the new residency segment at a different address.

The production portfolio compares \texttt{dist-size-cost} and \texttt{share-adaptive-25}. The former combines next-use distance, size, and static traffic cost. The latter changes priority when backed bytes are scarce or when a generated-only memory type has highly heterogeneous sizes. P2 enumerates early-reload windows $H\in\{0,5,40\}$; P3 uses $H\in\{0,5,40,80,120\}$. An early reload occurs only when a sufficiently large contiguous hole already exists and never evicts another resident, but it changes later residency state, so every window is evaluated as a complete candidate.

\begin{algorithm}[H]
\caption{Bounded P2/P3 artifact portfolio}\label{alg:supp-portfolio}
\begin{algorithmic}[1]
\Require Instance $I$ and problem number $q\in\{2,3\}$
\State $\mathcal O\gets\{$frontier, capfit-id, P1, id-raw$\}$
\State $\mathcal P\gets\{$dist-size-cost, share-adaptive-25$\}$
\State $\mathcal H\gets\{0,5,40\}$; if $q=3$, add $80,120$
\State $A^\star\gets\varnothing$
\For{$(O,P,H)\in\mathcal O\times\mathcal P\times\mathcal H$}
  \State generate topological order $\pi_O$
  \State generate addresses and spill artifact $A$ using best-fit, $P$, and $H$
  \If{placement fails} \State skip this infeasible portfolio member \EndIf
  \State compute $E,n_{\mathrm{spill}},T$ (the loop does not call the canonical evaluator)
  \State update $A^\star$ by $K_2=(E,n_{\mathrm{spill}},T)$ or $K_3=(T,E,n_{\mathrm{spill}})$
\EndFor
\State return $A^\star$; the experimental harness canonically evaluates the final artifact
\end{algorithmic}
\end{algorithm}

Algorithm~\ref{alg:supp-portfolio} considers at most $4\times2\times|\mathcal H|$ members and skips failed placements. It generates address/spill artifacts and computes the true objective for successful candidates; neither live area nor overflow area selects the winner. Production \texttt{solve} does not canonically evaluate every candidate inside the loop. The experimental harness validates the final selected artifact, and we report only zero-violation results. \subsection{A step-by-step reproducible small graph}

Table~\ref{tab:supp-toy-trace} is a pedagogical example manually expanded according to the current best-fit/spill implementation and canonical-evaluator rules. It shows how spill nodes, addresses, and charging form a P2 artifact; it is not a run log, public benchmark, or oracle datum and supports no numerical benchmark claim. Number the seven original nodes in the following order and connect consecutive nodes by the six edges $0\to1\to2\to3\to4\to5\to6$. The original topological order is therefore unique and directly checkable. Let one memory have capacity four; buffer $a$ is a two-byte backed input and $b$ a three-byte generated intermediate. The original order is
\[
 \operatorname{ALLOC}(a),\ \operatorname{COPYIN}(a),\
 \operatorname{ALLOC}(b),\ \operatorname{PRODUCE}(b),\
 \operatorname{FREE}(b),\ \operatorname{USE}(a),\ \operatorname{FREE}(a).
\]
There is no mandatory access to $a$ between COPY-IN and USE. At $b$'s allocation, logical live volume is five and best-fit cannot find a three-byte hole. Evicting $a$ lets $b$ occupy $[0,3)$. Because FREE is mandatory, $b$ remains resident through its FREE; $a$ is then reloaded before USE. Interrupting backed $a$ charges only two bytes.

\subsection{Offline cost repair and the fixed-order oracle}

The offline repair script observes expensive spill frontiers, proposes dependency-legal node or chain moves, replans the physical artifact, and accepts only strict P2-key improvements. Budgets are nonuniform: Conv\_Case0 uses 10,000 stochastic single-node hill proposals; Conv\_Case1 uses a width-10, two-round frontier beam; each FA instance receives 2,000 stochastic proposals with no accepted move; neither Matmul instance is searched. These studies only show that cost semantics may affect ordering in some cases. They are neither one uniform six-case algorithm nor a universal improvement.

The fixed-order oracle first solves weighted-gap selection in Eq.~\eqref{eq:supp-gap-obj}, then performs deterministic greedy packing trials and invokes an independent \texttt{NoOverlap2D} satisfaction model if needed. It emits the same schedule/memory/spill format as production and calls the same evaluator. On the eight internal 17-node oracle instances, production traffic under its \emph{own selected fixed order} is, respectively, 352, 1,408, 704, 704, 352, 1,408, 704, and 704. Every value equals the fixed-order CP-SAT lower bound and validates. This is fixed-order agreement on eight discrete small graphs, not evidence of large-scale exactness or global optimality across orders.

\subsection{Failures, unfinished cases, and reproduction boundary}

A complete account includes failures rather than retaining only certificates:
\begin{itemize}
  \item FA\_Case1 is a canonical-valid fixed-order FEASIBLE artifact with $E=32{,}512$, lower bound 31,936, and gap 576; it is not certified optimal.
  \item The reproducible 120.09-second Matmul\_Case0 run is FEASIBLE at 34,816 with lower bound 29,952. A legal heuristic artifact on the same order reaches 34,688, so the audited interval is $[29{,}952,34{,}688]$; the old ``34,688 OPTIMAL'' claim is revoked.
  \item Conv\_Case1 did not finish exact+packing within the research budget; Matmul\_Case1 was not run.
  \item Against official P3 time, the six public cases yield five wins and one loss. Conv\_Case1 is 1,118,687 versus 1,073,322, so dominance is not universal.
  \item Summary JSON can check metrics and validation status, but independent replay requires rerunning the deterministic solver when matching text artifacts are absent. Fixed-order certificates instead use machine JSON plus matching schedule/memory/spill files; older handwritten status cannot override machine records.
\end{itemize}

Address placement and residency scans make the production path scalable for a fixed portfolio. CP-SAT gap selection and fallback packing are exponential in the worst case. Canonical \texttt{solve} currently has no CP-SAT size threshold, timeout switch, or fallback integration, so oracle successes are not capabilities of the default solver.
