\section{Problem Definition and Evaluator Semantics}\label{sec:supp-problem}

This section states the complete contract among the input, output, and evaluator. The distinction matters: P1 logical-lifetime peaks, P2 physical residency segments, and P3 pipelined completion time are different objects and cannot substitute for one another. Likewise, the evaluator's backed/unbacked classification is not a dynamic hardware dirty bit.

\subsection{Input DAG and buffer lifetimes}

The input is a directed acyclic graph $G=(N,E)$ with three node classes:
\begin{enumerate}
  \item an \texttt{ALLOC} node creates a buffer;
  \item a \texttt{FREE} node ends that buffer's logical lifetime; and
  \item every other node is a compute or transfer operation listing the buffers it accesses, its execution pipeline, and its cycle count.
\end{enumerate}
Each buffer $b$ has a unique identifier, size $s_b$, memory type
$\tau(b)\in\{\mathrm{L1},\mathrm{UB},\mathrm{L0A},\mathrm{L0B},\mathrm{L0C}\}$,
a unique allocation node $a_b$, and a unique free node $f_b$. We call the occurrences of $b$ at operation nodes, together with $a_b$ and $f_b$, its \emph{mandatory events}. An original schedule
$\pi=(\pi_0,\ldots,\pi_{|N|-1})$ must contain every original node exactly once and satisfy
$\operatorname{pos}_\pi(u)<\operatorname{pos}_\pi(v)$ for every $(u,v)\in E$.

Two boundaries are easy to miss. First, the data record only which buffers an operation accesses; it does not expose per-access read/write roles. Second, the canonical evaluator treats \texttt{FREE} as a mandatory-residency event: a previously evicted buffer must be reloaded before it can be freed.

\subsection{P1: logical-lifetime peaks}

P1 emits neither addresses nor spills. For each memory type, the evaluator scans the original schedule, adding the size at \texttt{ALLOC} (or incrementing a buffer count for an L0 type) and subtracting it at \texttt{FREE}. The L1/UB metrics are therefore maxima of ALLOC/FREE prefix sums; the L0A/L0B/L0C metrics are maximum counts of simultaneously logically live buffers.

This is a \emph{logical-lifetime statistic}, not the bytes occupying physical addresses at a P2 instant. A logically live buffer may be temporarily evicted in P2. Conversely, the P1 peak contains neither address fragmentation, spill-out/spill-in nodes, nor address-reuse dependencies. P1 thus describes logical pressure induced by an order; by itself it does not prove that a legal contiguous-address layout exists.

\subsection{P2: contiguous addresses and explicit spill artifacts}

A P2 artifact has three parts: an augmented schedule $\widehat\pi$ containing synthetic spill-out/spill-in nodes, the initial residency address $m_b$ of every buffer, and an ordered spill table of pairs $(b,m'_b)$. Spill-table entry $j$ corresponds to two deterministically numbered synthetic nodes $o_j$ (spill-out) and $i_j$ (spill-in); $m'_b$ is the address of the new residency segment after reload.

A P2 artifact is legal exactly when it passes all of the following checks:
\begin{enumerate}
  \item \textbf{Coverage and topology:} every original and synthetic spill node occurs exactly once, and all original DAG dependencies hold.
  \item \textbf{Spill order:} $a_b\prec o_j\prec i_j\prec f_b$; no operation accesses $b$ between $o_j$ and $i_j$; and two spill intervals of the same buffer do not overlap.
  \item \textbf{Address range:} every residency segment occupies a half-open interval $[m_b,m_b+s_b)$ or $[m'_b,m'_b+s_b)$ wholly inside its memory capacity.
  \item \textbf{Space--time nonoverlap:} residency segments of the same memory type whose lifetimes overlap in schedule position must have disjoint address intervals.
\end{enumerate}
The fourth condition expresses both capacity and contiguity. Checking only that total bytes do not exceed capacity is insufficient: several small holes can have enough total space while no single hole fits a new contiguous segment.

\subsection{Static classes and the P2 objective}

The evaluator makes a \emph{static} binary classification. A buffer occurring in any \texttt{COPY-IN} operation is input-backed (abbreviated backed/clean); every other buffer is generated and unbacked (generated/dirty). The classification never changes during execution and does not infer whether an access is a read or a write.

Interrupting a backed buffer requires only a reload of $s_b$ bytes; interrupting an unbacked buffer requires a write-back and a reload, charging $2s_b$. Let $C$ and $D$ be the cumulative raw spill volumes of the two classes and let $V=C+D$. Extra traffic is
\begin{equation}\label{eq:supp-extra}
 E=C+2D=(C+D)+D=V+D.
\end{equation}
P2 lexicographically minimizes $K_2=(E,n_{\mathrm{spill}},T)$: extra traffic first, then the number of spill entries, then completion time. Every P2 comparison in the paper uses the matching official P2 artifact; values from official P3 artifacts are never mixed into that comparison.

\subsection{P3: pipelined time on the augmented DAG}

P3 uses the same physical legality conditions as P2, but makes augmented-schedule completion time the primary objective. For each node, the evaluator takes the maximum of all predecessor completion times, the availability time of the node's hardware pipeline, and the reuse-ready time of every address interval it occupies; it then adds the node's cycle count. Synthetic spill-out/spill-in nodes and their dependencies participate in the simulation. A pipeline is serialized, and a new residency segment reusing an address range waits for the previous segment to finish. The objective key is $K_3=(T,E,n_{\mathrm{spill}})$.

P2 and P3 are therefore not two spellings of the same objective. A wider early-reload window may increase traffic yet hide transfers behind computation and reduce $T$; P3 accepts that exchange when $K_3$ improves. We describe only the observed bounded-portfolio traffic--time tradeoff, not a global Pareto frontier.

\subsection{Validation, reproduction, and data scope}

We keep three levels distinct: a model objective, a generated physical artifact, and canonical-evaluator validation. A low relaxation objective is not a submission. We report an artifact as legal only after addresses, spill dependencies, and the schedule are generated and the evaluator returns zero violations. For the fixed-order exact backend, a JSON record together with matching schedule/memory/spill text files forms a replayable certificate; a metric-only ledger requires rerunning the deterministic solver to reconstruct the complete artifact.

Table~\ref{tab:supp-public-size} gives the original-node counts of the six public instances. The repository also contains 36 internal synthetic instances and eight 17-node fixed-order oracle instances. They support boundary and mechanism checks but are not additional public datasets. The solver has no case-name branch. However, the retained P1 fallback contains operation-type-specific tie-breaks, so the solver as a whole is not motif-agnostic; Section~\ref{sec:supp-solution} states the precise boundary.
